الحكم العام

المشروع في حالة جيدة للنشر ضمن نطاق الفحص الحالي: بنية PWA واضحة، بناء Vite يعمل، API القرآن متاح، وتكامل Supabase مهيأ مع سياسات RLS في ملفات SQL.

  • تم إصلاح مسار البحث الذي كان يعيد HTTP 500.
  • تم منع تخزين نسخة القرآن الكاملة في localStorage.
  • تمت معالجة أخطاء القراءة والحفظ في المزامنة السحابية.

حدود التحقق

التحقق الخارجي أثبت استجابة الخدمات وتهيئة المشروع، لكنه لم ينشئ مستخدماً ولم ينفذ تسجيل دخول حقيقياً أو اختباراً عملياً لحفظ بيانات مستخدم داخل الحساب.

  • يجب تشغيل SQL في مشروع Supabase إذا لم تكن الجداول موجودة بعد.
  • اختبار APK الفعلي يحتاج جهاز Android أو محاكي.

PRODUCT SURFACE · الوظائف

ماذا يقدم التطبيق؟

الميزات التالية مدعومة بمراجع واضحة في HTML وJavaScript الحاليين.

▤

قراءة المصحف

تحميل السور من alquran.cloud، عرض الآيات بنمط مصحف، أحجام خطوط متعددة، تبديل السور والأجزاء، وحفظ آخر موضع.

◉

التلاوة الصوتية

وضع السورة الكاملة ووضع آية بآية، تحكم بالتشغيل والسرعة والتكرار والتنقل، وMedia Session آمن على Chrome Android. تظليل السورة لا يظهر إلا عند توفر timestamps مطابقة لملف MP3 نفسه.

⌕

البحث العربي

يجلب نسخة quran-uthmani مرة واحدة إلى الذاكرة ثم يبحث محلياً بعد إزالة التشكيل؛ لا يحفظ النسخة الكاملة في localStorage.

۩

التفسير والترجمة

واجهة اختيار تفسير أو ترجمة وتحميل تفسير الآية عبر API مع تخزين مؤقت للاستخدام اللاحق.

☆

المفضلة والتقدم

حفظ السور والآيات، تتبع تقدم القراءة، واسترجاع آخر موضع محلياً مع إمكانية المزامنة عند تسجيل الدخول.

☁

المزامنة السحابية

تسجيل دخول بالبريد وكلمة المرور، ورفع المفضلة والإعدادات والتقدم إلى Supabase مع العودة للعمل محلياً دون حساب.

⌁

PWA وOffline

Manifest، Service Worker، كاش للـ shell وAPI والصوت، وصفحة offline.html عند انقطاع الشبكة.

↥

التثبيت والتحديث

تثبيت PWA، إعداد Capacitor للتطبيق الأصلي، وفحص version.json لإظهار تحديث APK عند توفره.

◐

تجربة الاستخدام

RTL، وضع ليلي ونهاري، تصميم متجاوب، Media Session للتلاوة، Toast notifications، واختصارات لوحة المفاتيح.

ARCHITECTURE · البنية

مسار البيانات

فصل واضح بين واجهة التطبيق ومصادر القرآن والتخزين الاختياري.

واجهة المستخدم

index.html + css/style.css تعرض السور والآيات والنوافذ وإعدادات القراءة.

منطق التطبيق

js/app.js يدير الحالة، التحميل، الصوت، البحث، المفضلة، الكاش وService Worker registration.

مصادر المحتوى

alquran.cloud للنص والتفسير، وموارد MP3 الخارجية للتلاوة. لا يخزن Supabase نص القرآن.

التخزين والمزامنة

localStorage للعمل المحلي، ثم Supabase Auth وPostgreSQL لمزامنة بيانات المستخدم عند توفر الحساب.

استراتيجية الكاش

  • كاش للبيانات لمدة 30 يوماً حسب إعداد التطبيق.
  • نسخة القرآن المستخدمة للبحث تبقى في الذاكرة فقط.
  • الكاش الصوتي محدود إلى 50 ملفاً في Service Worker.
  • مسار offline يحسب موقع التطبيق ديناميكياً.

BACKEND · SUPABASE

حالة قاعدة البيانات

مهيأة للمستخدمين والمزامنة، وليست مستودعاً لنص القرآن.

الربط الحالي

  • العميل مهيأ في js/supabase-config.js.
  • ترتيب التحميل في index.html: مكتبة Supabase ثم config ثم auth.
  • جدول المزامنة: quran_pro_user_data.
  • الحقول المستخدمة: bookmarks، reading_progress، settings، last_position، last_sync.
  • المستخدم الجديد مدعوم عبر maybeSingle().

ما تم إثباته وما لم يُثبت

تم إثباته: عنوان المشروع يستجيب، REST يصل إلى الجدول، وAuth settings تستجيب.

لم يتم إثباته في هذا الفحص: إنشاء حساب أو تسجيل دخول حقيقي، أو تنفيذ upsert ببيانات مستخدم فعلية. هذا اختبار يحتاج بيانات اعتمادك ولا يتم تنفيذه تلقائياً.

مخطط SQL

quran_pro_user_data

سجل واحد لكل مستخدم للمفضلة والتقدم والإعدادات والموضع الأخير.

quran_pro_stats

إحصائيات القراءة: الآيات، دقائق الاستماع، السلسلة اليومية والإنجازات.

RLS

سياسات SELECT/INSERT/UPDATE/DELETE تعتمد على auth.uid() = user_id في ملفي SQL.

ملاحظة أمنية

مفتاح Supabase المستخدم هو مفتاح anon العام، وظهوره في تطبيق الويب متوقع. الأمان الحقيقي يعتمد على RLS وعدم استخدام service-role key في المتصفح.

قبل الإنتاج، راجع سياسات RLS من لوحة Supabase وتأكد أن الجداول مفعلة فعلياً في المشروع الصحيح.
