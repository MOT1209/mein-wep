الخلاصة بصراحة

أيضاً: style.min.css المُعلَن أنه "مضغوط" في تحديث 09-04 هو نسخة طبق الأصل بايتاً بايت من style.css غير المضغوط — الإصلاح لم يُنفَّذ فعلياً رغم توثيقه كمكتمل.

💡 الأولوية الفورية ليست أداءً هذه المرة، بل نطاق النشر: امنع نشر linguaverse/، denkmalen/، mcp/، notebooks/، tools/، agents/، docs/، .pi/ — لا شيء من هذه المجلدات مرتبط من أي صفحة في الموقع.

02 اكتشافات جديدة

ثلاثة اكتشافات تم التحقق منها فعلياً بتنفيذ npm run build وفحص dist/ الناتج — وليست تخميناً.

🕳️ نسخ Passthrough في Eleventy ينشر مجلدات غير موثَّقة وغير مرتبطة بالموقع

حرج

eleventy.config.mjs يبني قائمة استثناءات (VERCEL_IGNORE) لحساب "ما يجب أن يُخدَّم"، لكنه بعدها ينفّذ addPassthroughCopy(dir) على كامل المجلد الجذري لكل اسم موجود في القائمة — وهذا لا يطبّق أي استثناء على الملفات الفرعية. النتيجة: أي مجلد جذري به ملف متتبَّع واحد فأكثر يُنسخ بالكامل إلى dist/ ويُنشر، بصرف النظر عمّا تقوله قائمة الاستثناء.

الدليل — تم تنفيذه فعلياً
$ npm run build && find dist -maxdepth 1 -iname "linguaverse" -o -iname "denkmalen" -o -iname "mcp" -o -iname "notebooks"
dist/linguaverse   (1.8MB — مشروع أندرويد كامل غير مرتبط بالمشروع)
dist/denkmalen     (2.0MB — أصول لعبة "Draw Battle" منفصلة تماماً)
dist/mcp           (160KB — يتضمن __pycache__/*.pyc مُترجَمة)
dist/notebooks     (16KB  — colab_train_king2_qwen25_3b.ipynb)
dist/.pi, dist/tools, dist/agents, dist/docs   (سكربتات ومحتوى داخلي)

تم فحص كل هذه المجلدات يدوياً بحثاً عن أسرار (grep على أنماط API keys/tokens) — لم يُعثر على أي سرّ فعلي مسرّب. لكن المشكلة قائمة: كود مصدري كامل لتطبيق أندرويد آخر (linguaverse)، وسكربتات تشغيل داخلية (tools/deploy_king2_platform.py, tools/point_king2_to_mein_wep_db.py)، ونوت‌بوك تدريب موديل، تُنشر علناً على نطاق الموقع رغم أنها غير مذكورة في README.md وغير مرتبطة من أي صفحة HTML. هذا هو نفس نوع "الانزلاق غير المقصود" الذي دفع لإنشاء .vercelignore أصلاً (بحسب تعليقه الخاص عن حادثة apps/quran-app/android/ السابقة) — والحماية التي بُنيت حينها لا تعمل مع أسلوب النسخ الحالي.

📦 50MB من ملفات APK ثنائية داخل Git — و.git بلغ 105MB

عالية
الوضع الحالي
  • apks/*.apk — 9 ملفات، ~50MB إجمالاً
  • إصداران محفوظان لكل تطبيق (مثال: calculator-app v1.0.0 و v1.0.1 = 13.2MB معاً)
  • .git/ الآن 105MB — كل استنساخ مستقبلي يحمّل هذا الوزن كاملاً
لماذا يزداد سوءاً
  • كل تحديث APK يضيف نسخة ثنائية جديدة إلى التاريخ — لا يُستبدل القديم أبداً
  • تنظيف التاريخ لاحقاً يتطلب git filter-repo أو BFG — عملية مزعجة وتؤثر على كل من استنسخ المستودع

البديل الأنسب لملفات توزيع ثنائية متغيّرة الإصدار: Git LFS، أو استضافتها كـ GitHub Releases assets، أو تخزين كائنات (Supabase Storage / R2) مع رابط تنزيل مباشر — مع الإبقاء على apks/updates.json فقط داخل Git.

🗜️ style.min.css ليس مضغوطاً فعلياً — رغم توثيقه كإصلاح مكتمل (F2)

متوسطة
الدليل
$ diff css/style.css css/style.min.css
(بدون أي فرق — الملفان متطابقان بايتاً بايت، 109,249 بايت لكل منهما)

تقرير 09-04 يذكر أن F2 نُفّذ ("ضُغط من 142KB إلى ~107KB مع نسخة style.min.css مطابقة") — لكن الملفين الحاليين متطابقان تماماً وغير مضغوطين (بلا إزالة تعليقات أو مسافات). أياً كانت الصفحة التي تشير إلى style.min.css، فهي تحصل على نفس الحجم الكامل. يحتاج تشغيل فعلي لأداة ضغط (esbuild / lightningcss / cssnano) ضمن npm run build بدلاً من نسخ يدوي.

04 الأمان — إعادة الفحص

ما تم التحقق منه وهو جيد

بوابة فحص أسرار في CI ممتاز

  • .github/workflows/ci.yml يفحص أنماط AIza…، sk-proj/ant-…، AKIA…، وتعيينات SERVICE_ROLE/SECRET في كل push
  • الفحص اليدوي بنفس الأنماط على كامل الشجرة الحالية لم يُظهر أي سرّ فعلي مسرّب

إدارة المفاتيح جيد

  • GEMINI_API_KEY وGITHUB_TOKEN في process.env فقط
  • لا service_role في أي ملف عميل — فقط إشارات نصية توضيحية في تعليقات/سكربتات أدوات

مشاكل لا تزال قائمة

XSS محتمل عبر innerHTML + error.message

متوسطة — لم تُصلَح منذ 09-04
models/Rashid-Model/script.js
L459:  imageResult.innerHTML = `...${error.message}...`;
L1244: resultContainer.innerHTML = `...${error.message || '...'}...`;

الملف نفسه يحتوي على دالة تنظيف جاهزة (سطر 37-39: div.textContent = text; return div.innerHTML;) لكنها غير مطبَّقة على مسارات الخطأ هذه. إن أعاد أي طرف علوي (خدمة ترجمة، توليد صورة) رسالة خطأ تحتوي HTML يتحكم به المستخدم، يُنفَّذ مباشرة. الإصلاح بسيط: مرّر error.message عبر نفس دالة التنظيف الموجودة بالفعل قبل الحقن.

للسياق: من أصل 129 استخدام innerHTML عبر 33 ملفاً، الغالبية العظمى قوالب ثابتة (أيقونات، spinners) منخفضة الخطورة — هذان الموقعان هما الاستثناء الفعلي الجدير بالإصلاح.
